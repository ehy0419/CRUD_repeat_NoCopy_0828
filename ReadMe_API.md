# RESTFul API
## Login, Logout (세션 사용)
| Method | 엔드포인트   | 설명       | 파라미터  | RequestBody                                     | Response | 정상 코드       | 에러 코드                                                     |
|--------|----------|----------|-------|-------------------------------------------------|------------------|-------------|-----------------------------------------------------------|
| POST   | /login   | 로그인      | -     | {<br/>”email”: string, “password”: string<br/>} | "로그인 성공"         | 201 CREATED | 400 BAD REQUEST <br/>403 FORBIDDEN                        |
| POST   | /logout  | 로그아웃     | -     | -                                               | "로그아웃 성공"         | 200 OK      | 400 BAD REQUEST <br> 401 UNAUTHORIZED <br> 404 NOT FOUND  |

### 수정하면서 궁금한 점
로그인에서 201 Created 보다 200 Ok 를 권장하는 이유 (세션만 생성), 실패는 400 BAD REQUEST <br/>403 FORBIDDEN 에서 400 BAD REQUEST, 401 UNAUTHORIZED 하는 이유
로그아웃에서 메시지 본문 없이 204 NO CONTENT, 메시지 본문이 있으면 200 OK

## Schedule 일정
| Method | 엔드포인트           | 설명       | 파라미터                           | RequestBody                                                                                                         | Response                                                                                                                                                                          | 정상 코드          | 에러 코드  |
|--------|-----------------|----------|--------------------------------|---------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------|--------------------------------------|
| POST   | /schedules      | 일정 생성    | SESSION<br/>-`LOGIN_USER` Long | {<br/>”userName”: string,<br/>”title”: string,<br/>”content”:string<br/>, ”startsAt”:string, <br/> ”endsAt”:string} | {<br/> ”id”: long,<br/> ”userId”:long,<br/> ”userName”: string,<br/> ”title”:string,<br/> ”content”:string,<br/> ”createdAt”: string,<br/> ”updatedAt”: string<br/> }             | 201 CREATED    | 400 BAD REQUEST<br/>401 UNAUTHORIZED |
| GET    | /schedules      | 모든 일정 조회 | -                              | -                                                                                                                   | [<br/> {<br/> ”id”: long,<br/> ”userId”:long,<br/> ”userName”: string,<br/> ”title”:string,<br/> ”content”:string,<br/> ”createdAt”: string,<br/> ”updatedAt”: string<br/> }<br/> ] | 200 OK         | 404 NOT FOUND |
| GET    | /schedules/{id} | 단일 일정 조회 | PATH<br/>-`id` Long            | -                                                                                                                   | {<br/> ”id”: long,<br/> ”userId”:long,<br/> ”userName”: string,<br/> ”title”:string,<br/> ”content”:string,<br/> ”createdAt”: string,<br/> ”updatedAt”: string<br/> }             | 200 OK         | 404 NOT FOUND |
| PUT    | /schedules/{id} | 일정 수정 | PATH<br/>-`id` Long            | {<br/> ”title”:string,<br/> ”content”:string<br/> }                                                                 | {<br/> ”id”: long,<br/> ”userId”:long,<br/> ”userName”: string,<br/> ”title”:string,<br/> ”content”:string,<br/> ”createdAt”: string,<br/> ”updatedAt”: string<br/> }             | 202 ACCEPTED   | 400 BAD REQUEST<br/>401 UNAUTHORIZED<br/>404 NOT FOUND |
| DELETE | /schedules/{id} | 일정 삭제 | PATH<br/>-`id` Long            | -                                                                                                                   | "일정이 삭제되었습니다."                                                                                                                                                             | 204 NO CONTENT | 401 UNAUTHORIZED<br/>404 NOT FOUND  |

### 수정하면서 궁금한 점
리소스 수정 PUT, PATCH 에서 202 Accepted는 비동기 처리 의미라 부적합. 대개 200 OK(갱신된 리소스 반환) 또는 204 No Content.
202 ACCEPTED 에서 200 OK, 204 No Content
